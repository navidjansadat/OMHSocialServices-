## Render deployment

This project is configured for a **single Render web service with a persistent disk**. Render's default filesystem is ephemeral; the persistent disk keeps the SQLite database and uploaded images across restarts and deploys. Persistent disks require a paid Render service.

1. Push this project to GitHub.
2. In Render, create a Blueprint/Web Service from the repository.
3. Use the included `render.yaml`.
4. Set `ADMIN_PASSWORD` to a strong password (12+ characters recommended).
5. `SESSION_SECRET` is generated by Render automatically by the Blueprint.
6. Deploy and open `/admin` for the management panel.

The app listens on Render's `PORT` and binds to `0.0.0.0`. Health check: `/healthz`.

## Local run

```bash
npm install
npm start
```

For local development, copy `.env.example` to `.env` and set your own credentials.

## Images

Admins can choose PNG/JPG/WebP/GIF images up to 4MB directly from a phone or computer. The server validates the image and stores it under the Render persistent disk (`/var/data/uploads`), so a separate image-hosting service is not required.

Do not commit `.env` or real production secrets to GitHub.
